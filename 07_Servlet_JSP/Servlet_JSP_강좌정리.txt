5. 서블릿(Servlet)

  1)특징
    - *.java
    - 저장위치는 src/main/java에 저장
    - 반드시 패키지 필수 (****)
    - main 메서드가 없음. 시작점이 없다.
     ( 이유는 사용자가 맨 처음 요청하는 서블릿이 시작점이 됨 )

   - 직접 new하지 않음.
     Tomcat 서버가 필요한 시점에 생성부터 소멸까지 관리해줌.
     즉 Tomcat 서버가 필요한 이유가 Servlet/JSP 같은 동적컴포넌트를 관리함.

    - 실행결과는 html로 나옴.

 2) 구현 방법 (외우기)

     가. 패키지로 구성
        ex. com.servlet

     나.  extends HttpServlet   (  jakarta.servlet.http 패키지 )

              <!-- 서블릿맵핑 -->

		<servlet-name>WorldServlet</servlet-name>
		<servlet-class>com.servlet.WorldServlet</servlet-class>
	    </servlet>
	   <servlet-mapping>
		<servlet-name>WorldServlet</servlet-name>
		<url-pattern>/world</url-pattern>
	    </servlet-mapping>	    
 
	  ===> Spring Framework에서 내부적으로 사용되는 서블릿(DispatcherServlet, / 으로 매핑되어있음)을 
	      매핑하는 방법임.

6. 서블릿 LifeCycle

   - Tomcat 컨테이너가 Servlet의 LifeCycle(생성~소멸)관리함.
    생성 때 자동 호출되는 콜백메서드(시스템이 호출하는 메서드) 제공 : init()
    소멸 때 자동 호출되는 콜백메서드 (시스템이 호출하는 메서드) 제공 : destroy()
    요청 때 자동 호출되는 콜백메서드 (시스템이 호출하는 메서드) 제공 : doGet/doPost

   1) init() 메서드
      - 서블릿이 생성될 때 자동으로 호출됨.
      - 한번만 호출됨

   2) doGet/doPost 메서드 <== 서비스 메서드라고 부름.
   
      - 서블릿에 요청할 때 자동으로 호출됨.
      - 요청할 때마다 매번 실행됨. (*********************************)

       코드구현:
             doGet(HttpServletRequest request, 
	           HttpServletResponse response){}

             doPost(HttpServletRequest request, 
	           HttpServletResponse response){}

	==> HttpServletRequest 와 HttpServletResponse는 로컬변수이기 때문에
	   결국 요청할 때마다 매번 새롭게 생성되고 제거됨. (************************************ X 100)

   3) destroy() 메서드
     - 서블릿이 삭제될 때 호출
     - 단 한번 호출됨

   ==> 최종 결론:  서블릿은 단 한번만 생성되고 
                여러 사용자 요청을 하나의 서블릿으로 처리함. (****************)
		따라서 인스턴스 변수로 만들면 여러 사용자가 공유할수 있음.(보안이슈)
		해결은 개별적인 변수를 가질수 있도록 로컬 변수로 만들어야 된다.



7. 서블릿의 thread-safe 와 thread-unsafe

   1) 서블릿의 2가지 변수 사용시 공유하거나 공유하지 않는 개념
      - 공유하면 thread-unsafe ( 인스턴스 변수)
        공유안되면 thread-safe  ( 로컬 변수 )
 
   2) 인스턴스 변수
       - 서블릿은 단 한번만 생성되기 때문에 인스턴스 변수도 단한번만 생성됨.
         따라서 여러 사용자들과 공유할 수 있기 때문에 안전하지 않게됨.

  3) 로컬변수
       - doGet/doPost메서드내의 로컬변수는 요청할 때마다 실행되는 메서드이기 때문에
         여러 사용자들과 공유되지 않음. 따라서 안전함. (******************)

8. 응답처리
                 요청 ( HttpServletRequest )
    웹브라우저 ---------------------> 서버
           <--------------------
	        응답   (HttpServletResponse )

  1) 개념
    - 서블릿에서 html작성해서 웹브라우저에게 전달하는 작업의미.
    - HttpServletResponse API가 처리함.


  2) 구현방법

      가.  MIME타입 지정
         - 서버의 서블릿이 웹브라우저에게 전달되는 데이터 종류(MIME타입)를 알려주는 작업의미.

	 문법:
	     response.setContentType("MIME타입지정");

	     response.setContentType("text/html"); // text/plain (일반텍스트)

     나.  출력시 사용하는 API 이용

         문법:
	      PrintWriter out = response.getWriter();

     다. html 출력

         문법:
	        out.print("<html>");

		..
		out.print("</html>");
