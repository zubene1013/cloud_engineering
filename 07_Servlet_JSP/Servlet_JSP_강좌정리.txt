6. 서블릿 LifeCycle

   - Tomcat 컨테이너가 Servlet의 LifeCycle(생성~소멸)관리함.
    생성 때 자동 호출되는 콜백메서드(시스템이 호출하는 메서드) 제공 : init()
    소멸 때 자동 호출되는 콜백메서드 (시스템이 호출하는 메서드) 제공 : destroy()
    요청 때 자동 호출되는 콜백메서드 (시스템이 호출하는 메서드) 제공 : doGet/doPost

   1) init() 메서드
      - 서블릿이 생성될 때 자동으로 호출됨.
      - 한번만 호출됨

   2) doGet/doPost 메서드 <== 서비스 메서드라고 부름.
   
      - 서블릿에 요청할 때 자동으로 호출됨.
      - 요청할 때마다 매번 실행됨. (*********************************)

       코드구현:
             doGet(HttpServletRequest request, 
	           HttpServletResponse response){}

             doPost(HttpServletRequest request, 
	           HttpServletResponse response){}

	==> HttpServletRequest 와 HttpServletResponse는 로컬변수이기 때문에
	   결국 요청할 때마다 매번 새롭게 생성되고 제거됨. (************************************ X 100)

   3) destroy() 메서드
     - 서블릿이 삭제될 때 호출
     - 단 한번 호출됨

   ==> 최종 결론:  서블릿은 단 한번만 생성되고 
                여러 사용자 요청을 하나의 서블릿으로 처리함. (****************)
		따라서 인스턴스 변수로 만들면 여러 사용자가 공유할수 있음.(보안이슈)
		해결은 개별적인 변수를 가질수 있도록 로컬 변수로 만들어야 된다.



7. 서블릿의 thread-safe 와 thread-unsafe

   1) 서블릿의 2가지 변수 사용시 공유하거나 공유하지 않는 개념
      - 공유하면 thread-unsafe ( 인스턴스 변수)
        공유안되면 thread-safe  ( 로컬 변수 )
 
   2) 인스턴스 변수
       - 서블릿은 단 한번만 생성되기 때문에 인스턴스 변수도 단한번만 생성됨.
         따라서 여러 사용자들과 공유할 수 있기 때문에 안전하지 않게됨.

  3) 로컬변수
       - doGet/doPost메서드내의 로컬변수는 요청할 때마다 실행되는 메서드이기 때문에
         여러 사용자들과 공유되지 않음. 따라서 안전함. (******************)

10. scope

  1) 개념
    - 자바의 변수 ( 로컬변수, 인스턴스변수, static변수 )처럼 
      tomcat컨테이너가 자동으로 데이터를 관리(저장,조회,수정,삭제)하는 3가지 객체의 lifecycle 의미함.


  2) 종류

    가. request scope (HttpServletRequest)
	
	-저장
	      request.setAttribute(String key, Object obj);
	-조회
	      Object obj = request.getAttribute(String key);
	-삭제
	      request.removeAttribute(String key);

	
     scope(Lifecycle)?
         - 요청 ~ 응답 
	 - doGet(doPost)메서드안에서만 사용이 가능함(********************) 

      용도:  게시판 목록보기



    나. session scope ( HttpSession)
	# 세션(저장소)이 있으면 리턴하고 없으면 새로생성해서 리턴
        HttpSession session = request.getSession();
	HttpSession session = request.getSession(true);
	------------------------------------------------
	# 세션(저장소)이 있으면 리턴하고 없으면 null 리턴
	HttpSession session = request.getSession(false);

	-저장
	      session.setAttribute(String key, Object obj);
	-조회
	      Object obj = session.getAttribute(String key);
	-삭제
	      session.removeAttribute(String key);

	scope(Lifecycle)?
	   - 웹브라우저와 scope가 동일 (동일 웹브라우저)
	     하지만 보안때문에 time-out 지정해서 일정시간(기본:30분)이 지나면 웹브라우저를 종료하지 않아도 세션이 제거된다.
	       
	      Server의 web.xml에서 다음과 같이 설정되어 있음 (단위 30분)
	            <session-config>
			<session-timeout>30</session-ti초eout>
		    </session-config>
		
		    또는
		    자바코드로 설정 가능
		    session.setMaxInactiveInterval(초);

         용도:  로그인, 장바구니


    다. application scope (ServletContext)
	ServletContext ctx = getServletContext();

	-저장
	      ctx.setAttribute(String key, Object obj);
	-조회
	      Object obj = ctx.getAttribute(String key);
	-삭제

	scope(Lifecycle)?
	  - tomcat 컨테이너와 scope가 동일

        용도:  블로그 방문자수

	그런데 실제 서비스되는 웹어플리케이션은 이전페이지를 현재페이지가 인식해서 동작됨.
